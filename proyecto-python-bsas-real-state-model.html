Project Overview

This project focuses on the study of property sales across Buenos Aires, Greater Buenos Aires, and the Atlantic Coast, utilizing information from various real estate portals such as Zonaprop and Properati, among others.

A non-linear model was successfully developed to predict their prices in different areas by leveraging various features provided by each seller and performing statistical analysis on sets of these features.

This project aims not only to predict the price of these properties but also to identify overestimated and underestimated prices, recognize negotiation opportunities, as well as spot potential fraud, among many other applications.

How we turn messy data into someting usefull?

To begin with, one of the first approaches one can take to predict property prices is to use a linear model by solely observing the average price per square meter and the total square meters of the property. If we do this and plot the results, we will obtain a distorted and messy first approximation of the data, as shown in the image—which is incredibly chaotic!

One of the first conclusions we can draw from looking at this graph is that a property's price cannot be uniquely estimated by its value per square meter and its total area. There are several factors that can cause this value to increase or decrease: ranging from the neighborhood or area where it is located, the distribution of covered and uncovered areas, the age of the property, the amenities it possesses, etc.

About the Model

To understand how the model works, it is essential to know the information collected in the dataset for its use. This dataset contains information not only about the sale price, areas (total, covered, and uncovered), and property type, but also the exact location of each analyzed property (not just latitude and longitude, but they are also divided with unique tags to group them by regions, neighborhoods, and/or specific localities).

It also contains information regarding the number of rooms, bathrooms, and the overall condition of the property.

In turn, each property keeps a record of over sixty possible unique features listed by the sellers, which we refer to as amenities. A single property usually does not contain even a third of all the tracked features, so the way we implement these variables into the model will add robustness and allow us to improve the model's accuracy.

This will be explained in greater detail later, but a primary characteristic of using so many variables is that not possessing some of these features will not affect the property's price prediction, either for better or for worse. However, this large number of variables allows us to evaluate behaviors in specific areas that will indeed vary the price for possessing these features.

All these features were collected in a way that makes them easily recognizable across the different real estate portals.

The equation that allows us to estimate the prices is the following:

$$ \hat{P}_i = M_{z,t} \left( S_{cov} + \alpha S_{uncov}\right) \exp\left\{ \beta_{0,z} + \sum_{j=1}^{K} \beta_{j,z} \left[ \frac{x_{i,j}}{\max(|X_{j,z}|)} \right] \cdot W_{j,z} \right\} $$
  • \(\hat{P}_i\): Represents the estimated total price for property \(i\).
  • \(M_{z,t}\): The base or reference value (price per square meter) of zone \(z\) and type of property \(t\).
  • \(S_{cov}, S_{land}\): Covered surface and total land surface (generally treated with logarithms to smooth variances).
  • \(\beta_{0,z}\): Model intercept or baseline bias calibrated for zone \(z\).
  • \(\beta_{j,z}\): Statistical adjustment coefficient corresponding to feature \(j\) in zone \(z\).
  • \(x_{i,j}\): Specific value of feature \(j\) observed in property \(i\).
  • \(\max(|X_{j,z}|)\): Normalization factor, corresponding to the maximum absolute value of variable \(j\) in zone \(z\).
  • \(W_{j,z}\): Standardized weight assigned to feature \(j\) to regulate its impact on the model using Machine Learning.

To represent the individual characteristics of each property in a structured manner, the input variable vector \(X_i\) is constructed. This vector captures multiple dimensions of the property, organized into categories ranging from surface metrics to textual analysis of building amenities:

$$ \begin{aligned} X_i = \Bigg[ & \underbrace{\text{Year}_{con}, (\text{Year}_{con})^2, D_{new}, D_{null\_age}}_{\text{1. Temporal Structure (4 variables)}}, \\ & \underbrace{\ln(1 + \text{Dorm}), D_{null\_dorm}, \ln(1 + \text{Bath}), D_{null\_bath}}_{\text{2. Functional Structure (4 variables)}}, \\ & \style{font-size: 15%}{\underbrace{\left[ \ln(1+\text{Bath}) \cdot \ln S_{cov}\right], \left[\ln(1+\text{Dorm}) \cdot \ln S_{cov}\right], \left[\frac{\text{Bath}}{\max(1, \text{Dorm})}\right], \ln\left[\frac{S_{cov}}{\max(1, \text{Dorm})}\right], (S_{uncov} \cdot D_{House})}_{\text{3. Synergies & Functional Saturation (5 variables)}}}, \\ & \underbrace{\sum_{c=1}^{8} D_{cond} \, ,}_{\text{4. Condition Dummies (8 variables)}} \\ & \underbrace{\sum_{a=1}^{44} D_{fac} + D_{null\_fac}}_{\text{5. Amenities Textual Filter (45 variables)}} \Bigg] \end{aligned} $$
  • \(\text{Year}_{con}\): Construction year of the property to evaluate depreciation.
  • \(\text{Dorm, Bath}\): Number of bedrooms and bathrooms, including interaction variables (functional synergies).
  • \(D_{x}\): Indicator dummy variables (e.g., \(D_{new}\) for brand new properties, \(D_{cond\_c}\) for property condition categories).
  • \(D_{fac\_a}\): Set of dummy variables extracted from text indicating the presence of 44 different types of amenities (pool, multi-purpose room, security, etc.).

The way the model works is as follows: first, it identifies all the rows that will be used for the analysis. In our case study, we took properties categorized as 'Departamento', 'Casa', 'Penthouse' (PH), and 'Casa de quinta'. All of these are non-commercial properties, but this could be extended to more property types (office buildings, shops, land lots, etc.).

The variables to be used in the model are defined, and a Random Forest is applied to 80% of these properties to assign a weight to each of these variables. This not only helps adjust the coefficients to be determined by the model, but it also serves as a first filter to know which variables will be more influential than others.

Once this is done, the value of \(M_{z,t}\) is calculated for each of the neighborhoods and property types.

Next, an adjustment is made using Huber Regression to properly handle outliers by assigning them an appropriate weight. This is done in each neighborhood and for every property type available. With this, all the \(\beta\) coefficients are calculated by performing statistical analysis in each neighborhood. Finally, once all the model's coefficients are obtained, the predicted price is calculated and compared with the real one to compute the Absolute Percentage Error (APE). The mean value of all these gives us the overall average error of the model, the MAPE.

To estimate the value of \(\alpha\), we observed how the different variables reacted and how the global error varied for different values of \(\alpha\). It was observed that the value that minimized the error without losing logical coherence was \(\alpha=2\); for values greater than this, the error tends to an asymptotic value that does not differ from the one previously set.

Results

The results shown correspond to the error distributions (the APE) for each of the analyzed properties. What can be observed is that by using a large part of the features presented in the property listings, it is possible to estimate the price of each property by comparing them with properties in the same region or containing similar qualities. This opens up the possibility of spotting business opportunities, either because a property's price does not match that of its neighbors with similar properties, or by finding bargains when a property's price has been underestimated.

It is important to highlight the fact that a listed property should be under 'normal' conditions—that is, the seller provides as much information as possible—since the more detailed the property description is, the easier it will be for the model to estimate the price.

Next Steps & Future Work

As mentioned earlier, this project has several areas where it can be improved. Among these improvements, we have:

  • The dataset can be expanded by collecting information from other real estate portals to improve the model's statistics by zone.
  • The collected data is up to May 2026 and lacks updating capabilities, so automating the data collection would improve the statistics.
  • Incorporate new zones by expanding to different provinces like Santa Fe or Cordoba, where data is available in the analyzed portals.
  • Successfully analyze the sellers' descriptions in a robust manner to identify keywords that allow not only to fill gaps in the dataset but also to identify important variables that were not considered in the model due to a lack of information in different portals (such as the property's orientation).
  • Lastly, the development of a new portal so that any user can paste the link of the property they wish to analyze, allowing it to return a report on its estimated price. This also allows for saving new records and opens up the possibility of an automatic update of the dataset if incorporated correctly.
